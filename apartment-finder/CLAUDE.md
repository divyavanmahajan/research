## Running the app

### As an installed package (production)

```bash
uvx dmv-aptfind          # starts server on :8788, opens browser
```

### In development (two processes)

```bash
# Backend
cd backend
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
uvicorn main:app --reload --port 8000

# Frontend (separate terminal)
cd frontend
npm install
npm run dev        # Vite dev server → http://localhost:5173
```

Vite proxies `/api/*` to `localhost:8000`.

### Tests

```bash
# Backend (from repo root — uses src/dmv_aptfind package)
.venv/bin/python -m pytest tests/ -v

# Backend (from backend/ — uses local imports)
cd backend && PYTHONPATH=. pytest -v

# Frontend
cd frontend && npm run test
```

### Build and publish

```bash
./publish.sh           # patch bump, build, upload to PyPI, git tag
./publish.sh minor     # minor bump
PYPI_TOKEN=pypi-xxx ./publish.sh   # pass token explicitly
```

Or manually:
```bash
hatch build            # triggers npm build, bundles frontend into wheel
.venv/bin/twine upload dist/*
```

## Architecture

Two layouts coexist — development (two separate processes) and packaged (single uvicorn process):

| Mode | Frontend | Backend | Port |
|------|----------|---------|------|
| Dev | Vite dev server | FastAPI (`backend/`) | 5173 / 8000 |
| Packaged | Static files served by FastAPI | `src/dmv_aptfind/` | 8788 |

**Data lives exclusively in the browser** — `localStorage` key `apartment-finder-db` (JSON). The backend is a stateless proxy; it never stores anything.

### Package layout (`src/dmv_aptfind/`)

This is the canonical package used by `uvx dmv-aptfind`. It mirrors `backend/` with relative imports.

```
src/dmv_aptfind/
├── __init__.py
├── __main__.py          # CLI entry point — uvicorn + webbrowser
├── main.py              # FastAPI app; mounts StaticFiles after /api routes
├── routers/             # listing, search, parse_url, travel_times
├── services/
│   ├── qasa_client.py   # All GraphQL calls to api.qasa.se
│   ├── gmaps_client.py  # Google Maps internal directions API (all 4 modes)
│   └── url_parser.py    # Extract home_id from Qasa URL
├── models/              # Pydantic request/response schemas
└── static/              # Pre-built React frontend (gitignored, generated by hatch_build.py)
```

New endpoint checklist: add router in `src/dmv_aptfind/routers/` **and** `backend/routers/` → register in both `main.py` files → Pydantic models → tests first → service logic.

### Backend layout (`backend/`)

Used only in development. Imports are absolute (`from services.x import y`).

```
backend/
├── main.py
├── routers/
├── services/
├── models/
└── tests/
```

### Frontend layout

```

├── types/index.ts         # All shared TypeScript interfaces
├── store/useAppStore.ts   # Zustand store + localStorage persist middleware
├── api/qasaApi.ts         # Typed fetch wrappers (calls /api/*)
```

### Key constraints

- **All localStorage access goes through `utils/db.ts`** — never directly from components or the store.
- **All fetch calls go through `api/qasaApi.ts`** — never `fetch` directly from components.
- **Geocoding happens in the backend**, not the frontend (Nominatim CORS restriction).
- **All modals use `createPortal(…, document.body)`** — Leaflet applies CSS transforms to the map pane which creates a stacking context; portalling to body ensures modals always render above the map.
- Backend `POST /api/search` is capped at `MAX_PAGES = 9` (~531 results) to avoid multi-minute fetches on large cities.
- CORS middleware is **disabled by default** in the packaged `main.py` (frontend is co-located). Set `ALLOWED_ORIGINS=http://localhost:5173` for development if running the package against the Vite dev server.

### Commute times

Travel times use Google Maps' internal unauthenticated directions endpoint (`/maps/preview/directions`). All four modes (drive, transit, walk, cycle) are returned in a single request. Implementation is in `services/gmaps_client.py`. A browser `User-Agent` header is required.

### Search area identifiers

The area field uses Qasa's `country-code/city` format. Common values:

| City | Identifier |
|------|-----------|
| Gothenburg | `se/gothenburg` |
| Stockholm | `se/stockholm` |
| Malmö | `se/malmo` |
| Oslo | `no/oslo` |
| Helsinki | `fi/helsinki` |

### State management

Zustand store (`useAppStore`) holds: `apartments`, `savedSearches`, `searchResults`, `selectedApartmentId`, `activeTab`, `travelDestinations`. The `persist` middleware automatically syncs to localStorage. Schema migrations run in `db.ts` when `version` in stored JSON is behind `CURRENT_VERSION`.

### Testing patterns

**Backend** — mock httpx with `respx`:
```python
with respx.mock(base_url="https://api.qasa.se") as rx:
    rx.post("/graphql").mock(return_value=httpx.Response(200, json=MOCK_DATA))
```

For `gmaps_client`, patch with `unittest.mock.AsyncMock` (respx cannot intercept non-httpx clients):
```python
with patch("dmv_aptfind.routers.travel_times.get_all_travel_times",
           new=AsyncMock(return_value={"drive": 9, ...})):
```

**Frontend** — mock the API module, not fetch:
```typescript
vi.mock('../../../api/qasaApi', () => ({
  fetchListing: vi.fn().mockResolvedValue({ id: '123', ... }),
}));
```

Test files live in `frontend/src/test/` and are excluded from the production `tsc` build via `tsconfig.app.json`. `vite.config.ts` imports `defineConfig` from `vitest/config` (not `vite`) to support the `test` key.
